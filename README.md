# EventMatch — умный подбор подрядчиков

Проект команды Soda для HackAlem AI, кейс Firebird «Умный подбор подрядчиков» (#79-lite). Помогает выбрать до трёх подрядчиков из каталога своего города и объясняет выбор фактами из описаний.

## Что реализовано

### Python pipeline

Модульный Python-пайплайн находится в `src/`:

- `src/data_loader.py` — загрузка, очистка, даты и происхождение профилей;
- `src/filters.py` — город, категория, календарь, бюджет и дополнительные условия;
- `src/ranker.py` — детерминированное и семантическое ранжирование;
- `src/generator.py` — исходы поиска, промпты, объяснения и финальные карточки.

Точка входа: `main_pipeline.py`. Каталог расположен в
`data/hackathon-dataset-anonymized.jsonl`.

```bash
python main_pipeline.py
```

`sentence-transformers` и `pandas` перечислены в `requirements.txt` как
опциональные зависимости. Без `sentence-transformers` используется
детерминированный hashing fallback, а без ответа LLM — фактологический fallback
для объяснений.

- Интерфейс команды с сохранёнными оливковой палитрой, адаптивными страницами и карточками; подписи переведены на русский.
- Свободное описание → разбор через OpenAI → редактируемое подтверждение → подбор. При отсутствии AI доступна ручная форма.
- Исходные 66 профилей, 17 категорий, исходные идентификаторы и флаги происхождения. Демонстрационные 12 профилей заменены исходным каталогом.
- Строгая серверная проверка города, категории, формата, бюджета, даты, указанного языка и часов работы подрядчика.
- До трёх карточек; отдельные состояния отсутствующей категории и отсутствия совпадений. Причины исключения видны пользователю.
- Объяснения из точных фрагментов исходных описаний и проверенных полей. Никаких придуманных рейтингов, фотографий или отзывов.
- Изменение только даты сопровождается пояснением о занятости подрядчиков из предыдущей подборки.
- Подготовка фиксированного смыслового индекса через OpenAI Embeddings; после подготовки выбор пожеланий влияет на порядок.

Интеграция OpenAI реализована и проверяется тестовым HTTP-сервисом. Для проверки настоящего API требуется локальный ключ и подготовка индекса. Без них приложение честно работает в режиме строгой фильтрации и сортировки по цене. Наличие ключа в настройках само по себе не подтверждает доступность API.

## Запуск

Нужен **Go 1.22 или новее**. Сторонних Go-библиотек, Node.js, npm, сборки интерфейса и базы данных не требуется.

Из корня репозитория:

```bash
go run .
```

Открыть **http://127.0.0.1:8080**. Команда остаётся работать в терминале; остановка — `Ctrl+C`. Прямое открытие HTML-файла не подключает серверный подбор.

Для AI:

```bash
cp .env.example .env
```

Открыть `.env` в редакторе и указать `OPENAI_API_KEY`. Файл игнорируется Git; не вставляйте настоящий ключ в команды, README или сообщения. Настройки также можно задавать переменными окружения; они имеют приоритет над `.env`. `.env` не является shell-скриптом и поддерживает только перечисленные настройки `KEY=value`.

```bash
go run . -prepare
go run .
```

`-prepare` один раз отправляет 66 проверенных цитат и 12 описаний пожеланий в OpenAI, сохраняет нормализованные векторы в `data/semantic-index.json`. Существующий индекс команда не перезаписывает. Перезапустите сервер после изменения настроек или подготовки индекса. Если AI API недоступен, сервер всё равно можно запустить без индекса.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | пусто | Серверный ключ OpenAI API |
| `OPENAI_MODEL` | `gpt-4.1-mini-2025-04-14` | Разбор описания в поля |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` | Подготовка смыслового индекса, 512 измерений |
| `LISTEN_ADDR` | `127.0.0.1:8080` | Адрес сервера |

Текст свободного запроса отправляется в OpenAI; `store: false` передаётся при разборе. Пользователю предлагается не вводить контакты и персональные данные гостей. Во время поиска по подтверждённым параметрам запросов к внешнему AI нет. Модели можно сменить настройками, но доступ к конкретной модели зависит от аккаунта. Используются [Responses API со структурированным ответом](https://developers.openai.com/api/docs/guides/structured-outputs) и [Embeddings API](https://developers.openai.com/api/docs/guides/embeddings).

## Как устроен подбор

1. `POST /api/briefs` разбирает текст в обязательные поля, дополнительные ограничения и пожелания. Отсутствующие сведения остаются незаполненными. Сервер проверяет ответ модели, а пользователь подтверждает его в форме.
2. Пожелания представлены 12 редактируемыми направлениями: спокойная подача, динамичная программа, репортаж, постановочная съёмка, персональный подход, деловая атмосфера, традиции, минимализм, природа, интерактивы, живая музыка, цветочные композиции. Это ограничение первой версии, а не понимание любых пожеланий без потерь.
3. Условия вне доступных полей и направлений остаются в `unverified_requirements`. Поиск блокируется до уточнения или явного удаления этих условий пользователем. Например, «обязательно без конкурсов» нельзя молча заменить на «спокойная подача».
4. `POST /api/matches` отбирает кандидатов по строгим условиям. Описание не расширяет указанные в полях города, форматы или языки.
5. При наличии индекса и пожеланий сортировка использует среднюю близость фиксированных векторов выбранных пожеланий к вектору цитаты профиля. Затем — начальная цена и стабильный `id`. Без пожеланий или индекса — цена и `id`.
6. Объяснение собирается из проверенной цитаты и фактов о соответствии условиям. Смысловая близость не доказывает наличие услуги. Полный исходный текст доступен в профиле.

Компоненты: `main.go` — загрузка CSV, проверки, API и раздача интерфейса; `ai.go` — OpenAI и смысловой индекс; `Soda_UI/EventMatch/dist/` — существующий интерфейс команды. CSV и индекс загружаются в память при старте. Разбор AI ограничен 8 секундами; подготовка индекса — 45 секундами вне пользовательского поиска. Ошибка AI не ослабляет строгие условия.

### API

| Запрос | Вход | Ответ |
|---|---|---|
| `GET /api/options` | — | Допустимые значения полей, пожелания, период календаря и доступность AI |
| `POST /api/briefs` | `{"text":"описание мероприятия"}` | Параметры для подтверждения; пропуски остаются пустыми |
| `POST /api/matches` | Подтверждённые поля ниже | `status`, `cards`, `total`, `candidate_count`, `excluded`, `message`, `ranking`, `notice`, `data_version` |

Пример запроса при запущенном сервере:

```bash
curl http://127.0.0.1:8080/api/matches \
  -H 'Content-Type: application/json' \
  -d '{"city":"Алматы","event_date":"2026-10-06","event_type":"корпоратив","category":"Ведущий","budget_kzt":1300000,"language":"русский","duration_hours":6,"wishes":[],"unverified_requirements":[]}'
```

`language` можно опустить или передать пустой строкой; `duration_hours` — опустить или передать `null`. `wishes` содержит идентификаторы из `/api/options`. Цена — целое число тенге, часы могут быть дробными. Три бизнес-исхода возвращают HTTP 200: `matches_found`, `category_unavailable`, `no_matches`. Ошибки входных данных — 400/422, недоступный разбор AI — 503; тело ошибки: `{"error":{"code":"...","message":"..."}}`. Счётчики причин исключения могут пересекаться.

### Повторяемость

Сортировка не вызывает языковую модель и не вычисляет новые векторы запросов. Она использует неизменный индекс, фиксированный порядок суммирования, округление оценки до миллионных, цену и `id`. Дубли пожеланий удаляются, порядок их выбора не влияет на результат.

Гарантия относится к **одинаковым подтверждённым полям и пожеланиям при одинаковой версии данных, индекса и кода**. Первичный разбор свободного текста внешней моделью может различаться; поэтому поля показываются для подтверждения. `temperature=0` и кеш не используются как доказательство повторяемости.

Версия CSV, цитат и словаря пожеланий проверяется при загрузке индекса; устаревший индекс не используется. В ответе поиска есть `data_version`, включающий отпечаток самого индекса. После создания **сохраните `data/semantic-index.json` вместе с решением в Git**: в нём нет API-ключа. Один и тот же файл нужен для повторения смыслового порядка на другой машине. Повторная генерация через внешний API создаёт новую версию данных и может менять порядок.

## Данные и происхождение

`data/catalog.csv` — копия переданного организаторами CSV без изменения содержимого. HTML-превью не используется: в нём сокращены 39 описаний.

- 50 профилей Алматы, 15 Астаны, один с обозначением «Зарубежье». Выезды, упомянутые в описаниях, не расширяют поле города.
- 13 исходных синтетических профилей, восемь дополненных городов, 18 дополненных цен. Флаги сохранены и показаны в карточках. `data_origin: organizer` отличает их от добавлений команды; в рабочем каталоге добавлений команды нет.
- `data/evidence.json` — выбранные при разработке AI-агентом и проверенные цитаты, а не новые сведения о подрядчиках. При старте каждая цитата проверяется на буквальное присутствие в исходном описании.
- `max_hours` пусто у девяти профилей: услуга не привязана к присутствию на площадке. Такие записи не исключаются по длительности.
- `price_from_kzt` — цена «от» за мероприятие; не умножается на часы и не гарантирует итоговую стоимость.
- Занятость проверяется у всех, включая площадки. За пределами 23.09.2026–31.12.2026 подбор недоступен.

## Как проверить

```bash
go test -race ./...
go vet ./...
```

Тесты используют исходный каталог и локальный тестовый AI-сервис: проверяют ограничения, занятость площадок, редкие категории, пустую выдачу, непроверяемые условия, ошибки формата, происхождение цитат, сохранение и повторную загрузку индекса, изменение порядка по пожеланиям. Для этих тестов ключ и интернет не нужны. Контрольные векторы в тестах не являются результатом настоящей модели.

В интерфейсе есть кнопки трёх примеров, которые сначала открывают подтверждение:

| Сценарий | Условия | Ожидаемое поведение |
|---|---|---|
| Массовая категория | Алматы, ведущий, корпоратив, 06.10.2026, 1 300 000 ₸, русский, 6 ч, без пожеланий | Семь проходят условия; карточки: Куррапика, Мицури Канроджи, Аня Форджер |
| Повтор | Тот же запрос | Те же три карточки в том же порядке |
| Смена даты | Из предыдущего результата изменить только дату на 02.10.2026 | Кики и Буллма; объяснение исключения прошлой тройки по занятости |
| Редкая категория | Астана, флорист, свадьба, 01.10.2026, 300 000 ₸, русский | Хаку — единственный профиль категории в городе |
| Все заняты | Тот же флорист на 02.10.2026 | Нет совпадений, причина — занятость |
| Категории нет | Астана, декоратор, свадьба, 01.10.2026, 2 000 000 ₸ | Категории нет в этом городе |

После настройки AI проверьте текст: «Ведущий на корпоратив в Алматы 6 октября 2026, до 1 300 000 тенге, на русском, на 6 часов, спокойная подача». Убедитесь, что параметры и пожелание видны до подтверждения. Сравните с «динамичная программа» при тех же полях; конкретный смысловой порядок нужно проверить на подготовленном индексе, а не объявлять заранее.

## Ограничения

- Живая проверка OpenAI требует ключа. Без индекса смысловой подбор явно отключён; без ключа отключён разбор свободного текста.
- Смысловой индекс использует по одной выбранной цитате на профиль. Полные описания могут содержать дополнительные детали, которые не влияют на смысловой порядок первой версии.
- Автоматический разбор может ошибаться; подтверждение полей обязательно. Правильный JSON сам по себе не доказывает правильность понимания.
- Поля и описания иногда расходятся. Для строгих проверок приоритет у полей; заявления из описаний не считаются независимо подтверждёнными отзывами, наградами или гарантиями.
- Нет бронирования, заявок, оплаты, уведомлений, автоматического ослабления условий, дообучения и интеграции с API Firebird.
- Состояние формы хранится в памяти вкладки и сбрасывается при перезагрузке. Шрифты загружаются с Google Fonts; есть системный запасной шрифт.
- Сервер рассчитан на локальную демонстрацию. Публичное размещение и защита расходов API для публичного сервиса отдельно не настроены. Развёрнутой публичной версии нет.

При разработке использован AI-агент Codex: интеграция интерфейса, сервер, выбор цитат, тесты и документация. Итоговую версию необходимо сдать через платформу хакатона; отправка кода в GitHub сама по себе не является сдачей.
