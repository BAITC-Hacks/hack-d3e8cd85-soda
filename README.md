# EventMatch — умный подбор подрядчиков

Проект команды Soda для HackAlem AI, кейс Firebird «Умный подбор подрядчиков» (#79-lite). Помогает выбрать до трёх подрядчиков из каталога своего города и объясняет выбор фактами из описаний.

## Что реализовано

- Новая титульная страница, AI-консультант и три шага подтверждения в оливково-кремовой палитре команды. Компактная навигация сверху, адаптивные формы и карточки, без счётчика профилей в шапке.
- Свободное описание → разбор через OpenAI → редактируемое подтверждение → подбор. При отсутствии AI доступна ручная форма.
- Диктовка через микрофон → редактируемый текст → тот же сценарий подтверждения. Запись можно остановить или отменить.
- PostgreSQL хранит каталог, календарь, проверенные цитаты и происхождение данных. Изменения в БД учитываются при следующем запросе.
- Исходные 66 профилей, 17 категорий, исходные идентификаторы и флаги происхождения. Демонстрационные 12 профилей заменены исходным каталогом.
- Строгая серверная проверка города, категории, формата, бюджета, даты, указанного языка и часов работы подрядчика.
- До трёх карточек; отдельные состояния отсутствующей категории и отсутствия совпадений. Причины исключения видны пользователю.
- Объяснения из точных фрагментов исходных описаний и проверенных полей. Никаких придуманных рейтингов, фотографий или отзывов.
- Изменение только даты сопровождается пояснением о занятости подрядчиков из предыдущей подборки.
- Интерактивный календарь: занятость по месяцам и число свободных подрядчиков на каждый день с учётом выбранных условий.
- Для подходящих по остальным условиям, но занятых подрядчиков — отдельные предложения ближайших свободных дат. Изменение даты требует выбора и повторного подтверждения.
- Подготовка фиксированного смыслового индекса через OpenAI Embeddings; после подготовки выбор пожеланий влияет на порядок.

Интеграция OpenAI реализована и проверяется тестовым HTTP-сервисом. Для проверки настоящего API требуется локальный ключ и подготовка индекса. Без них приложение честно работает в режиме строгой фильтрации и сортировки по цене. Наличие ключа в настройках само по себе не подтверждает доступность API.

## Запуск

Нужны **Go 1.25 или новее** и **Docker с Compose** для PostgreSQL 17. Вместо Docker можно указать существующий PostgreSQL в `DATABASE_URL`. Единственная прямая Go-зависимость — драйвер PostgreSQL `pgx`; версии закреплены в `go.mod` и `go.sum`. Node.js, npm и сборка интерфейса не нужны.

Из корня репозитория:

```bash
docker compose up -d --wait db
go run .
```

Открыть **http://127.0.0.1:8080**. Команда остаётся работать в терминале; остановка — `Ctrl+C`. Прямое открытие HTML-файла не подключает серверный подбор.

Для AI:

```bash
cp .env.example .env
```

Открыть `.env` в редакторе и указать `OPENAI_API_KEY`. Файл игнорируется Git; не вставляйте настоящий ключ в команды, README или сообщения. Настройки также можно задавать переменными окружения; они имеют приоритет над `.env`. `.env` не является shell-скриптом и поддерживает только перечисленные настройки `KEY=value`.

```bash
go run . -prepare
go run .
```

`-prepare` один раз отправляет 66 проверенных цитат и 12 описаний пожеланий в OpenAI, сохраняет нормализованные векторы в `data/semantic-index.json`. Существующий индекс команда не перезаписывает. Перезапустите сервер после изменения настроек или подготовки индекса. Если AI API недоступен, сервер всё равно можно запустить без индекса.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | пусто | Серверный ключ OpenAI API |
| `OPENAI_MODEL` | `gpt-4.1-mini-2025-04-14` | Разбор описания в поля |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` | Подготовка смыслового индекса, 512 измерений |
| `OPENAI_TRANSCRIPTION_MODEL` | `gpt-transcribe` | Распознавание диктовки |
| `DATABASE_URL` | Локальная БД из `.env.example` | Подключение к PostgreSQL |
| `POSTGRES_PASSWORD` | `eventmatch_local` | Пароль при первом создании локальной БД через Compose |
| `POSTGRES_PORT` | `5432` | Локальный порт PostgreSQL в Compose |
| `LISTEN_ADDR` | `127.0.0.1:8080` | Адрес сервера |

Текст свободного запроса отправляется в OpenAI; `store: false` передаётся при разборе. Пользователю предлагается не вводить контакты и персональные данные гостей. Во время поиска по подтверждённым параметрам запросов к внешнему AI нет. Модели можно сменить настройками, но доступ к конкретной модели зависит от аккаунта. Используются [Responses API со структурированным ответом](https://developers.openai.com/api/docs/guides/structured-outputs) и [Embeddings API](https://developers.openai.com/api/docs/guides/embeddings).

### PostgreSQL и сохранность данных

Первый запуск в одной транзакции создаёт схему из `schema.sql` и переносит CSV с цитатами в БД. Ошибка откатывает импорт целиком; одновременные запуски сериализуются блокировкой. Повторный запуск видит отметку импорта и **не перезаписывает профили и календарь**, даже если файлы начального каталога изменены или отсутствуют.

Таблицы схемы `eventmatch`: `contractors` — профили и цитаты; `busy_dates` — даты занятости со ссылкой на профиль; `catalog_imports` — версия и время первоначального импорта; `schema_migrations` — применённая начальная версия схемы. Обязательные поля, цены, длительность, диапазон дат и присутствие цитаты в описании защищены ограничениями БД. Для каждого запроса сервер читает согласованный снимок каталога одним SQL-запросом. CSV нужен только для первичного наполнения, тестов и воспроизводимости исходных данных.

Данные находятся в постоянном томе `postgres_data`. `docker compose stop db` и `docker compose down` сохраняют его; `docker compose up -d --wait db` запускает БД снова. Не добавляйте `-v` к `down`, если данные нужно сохранить. При недоступной БД API возвращает 503 и не использует старый календарь из памяти.

Compose открывает порт только на `127.0.0.1`; пароль по умолчанию предназначен для локальной демонстрации. При смене порта или пароля согласуйте `DATABASE_URL` с настройками Compose. `POSTGRES_PASSWORD` задаёт пароль при создании тома: изменение `.env` само по себе не меняет пароль уже созданной БД. Для внешнего PostgreSQL укажите его адрес и настройки TLS в `DATABASE_URL`; пользователь БД должен иметь право создать схему и таблицы.

### Диктовка

На первом экране нажмите «Диктовать», разрешите микрофон, произнесите условия и нажмите «Остановить и распознать». Запись автоматически останавливается через 60 секунд. Текст дополняет уже введённое описание; его можно исправить перед кнопкой «Понять запрос». Подбор начинается только после отдельного подтверждения параметров.

Браузер записывает WebM или MP4 через встроенный `MediaRecorder`. Микрофон работает на `localhost`/`127.0.0.1` либо по HTTPS; открытие по обычному HTTP через адрес в локальной сети не подходит. Поддержка зависит от браузера и разрешения на микрофон. При отсутствии поддержки остаётся ввод текстом.

После остановки сервер отправляет аудио в [OpenAI Transcriptions API](https://developers.openai.com/api/docs/guides/speech-to-text); ключ остаётся на сервере. Наш лимит файла — 10 МиБ, ожидание OpenAI — до 8 секунд, клиентского запроса — до 10 секунд. Приложение не сохраняет аудио и тексты запросов в файлы или БД. Отмена во время записи не отправляет её; отмена после отправки прерывает ожидание, но уже переданные провайдеру данные отозвать нельзя. Отказ в доступе, ошибка записи или распознавания сохраняют предыдущее описание; при уходе с экрана микрофон выключается.

## Как устроен подбор

1. `POST /api/briefs` разбирает текст в обязательные поля, дополнительные ограничения и пожелания. Отсутствующие сведения остаются незаполненными. Сервер проверяет ответ модели, а пользователь подтверждает его в форме.
2. Пожелания представлены 12 редактируемыми направлениями: спокойная подача, динамичная программа, репортаж, постановочная съёмка, персональный подход, деловая атмосфера, традиции, минимализм, природа, интерактивы, живая музыка, цветочные композиции. Это ограничение первой версии, а не понимание любых пожеланий без потерь.
3. Условия вне доступных полей и направлений остаются в `unverified_requirements`. Поиск блокируется до уточнения или явного удаления этих условий пользователем. Например, «обязательно без конкурсов» нельзя молча заменить на «спокойная подача».
4. `POST /api/matches` отбирает кандидатов по строгим условиям. Описание не расширяет указанные в полях города, форматы или языки.
5. При наличии индекса и пожеланий сортировка использует среднюю близость фиксированных векторов выбранных пожеланий к вектору цитаты профиля. Затем — начальная цена и стабильный `id`. Без пожеланий или индекса — цена и `id`.
6. Объяснение собирается из проверенной цитаты и фактов о соответствии условиям. Смысловая близость не доказывает наличие услуги. Полный исходный текст доступен в профиле.

Компоненты: `main.go` — проверки, API и раздача интерфейса; `calendar.go` — общие правила фильтрации, календарь и альтернативные даты; `database.go` и `schema.sql` — PostgreSQL и первичный импорт; `ai.go` — OpenAI и смысловой индекс; `voice.go` — приём и распознавание аудио. В `Soda_UI/EventMatch/dist/`: `app.js` управляет состоянием и переходами, `pages.js` — страницами, `calendar.js` — выбором даты и занятостью, `voice.js` — диктовкой. Индекс загружается при старте, каталог читается из PostgreSQL на запросе с ограничением 3 секунды. Разбор AI ограничен 8 секундами; подготовка индекса — 45 секундами вне пользовательского поиска. Ошибка AI не ослабляет строгие условия.

### Календарь и альтернативные даты

Календарь находится на шагах «Событие» и «Проверка». Для расчёта обязательны город и категория; формат, бюджет, язык и длительность учитываются по мере заполнения. До этого дату можно выбрать без оценки занятости. Расчёт использует те же строгие правила, что и итоговый подбор. Непроверяемые требования и пожелания не входят в оценку занятости; последние меняют только порядок рекомендаций.

Число в дне — сколько подходящих по указанным условиям подрядчиков не имеют отметки о занятости. Процент за месяц — число занятых пар «подрядчик–день», делённое на число подходящих подрядчиков и число известных дней месяца; округляется до целого. Это занятость исходного каталога, не прогноз спроса. Сентябрь рассчитан только за 23–30 сентября; остальная часть календаря — октябрь–декабрь 2026. Если никто не проходит остальные условия, процент равен `null`, интерфейс показывает «Нет оценки», а не ложные 0% занятости.

Месяцы переключаются кнопками. По дням можно двигаться стрелками, `Home` и `End`; `Enter` выбирает дату. Дни без свободных кандидатов остаются доступными для выбора, дни вне покрытия отключены. Есть и обычное поле даты для ввода с клавиатуры. После изменения условий устаревший ответ календаря не заменяет новый.

Занятые на выбранный день **исключены из `cards`**. Отдельный блок предлагает до трёх подрядчиков, у которых только дата мешает совпадению. Для каждого показаны до трёх ближайших дней без отметки о занятости, в обе стороны от выбранной даты; при равном расстоянии сначала будущий день. Порядок самих подрядчиков соответствует правилам смыслового подбора/цены/id. Если свободных дней в периоде нет, это указано прямо. Выбор альтернативы меняет только дату и открывает подтверждение; повторный поиск проверяет актуальную БД. Гарантий бронирования нет.

### API

| Запрос | Вход | Ответ |
|---|---|---|
| `GET /api/options` | — | Допустимые значения полей, пожелания, период календаря и доступность AI |
| `POST /api/briefs` | `{"text":"описание мероприятия"}` | Параметры для подтверждения; пропуски остаются пустыми |
| `POST /api/transcriptions` | `multipart/form-data`, одно поле `audio`, WebM/MP4 до 10 МиБ | `{"text":"распознанная речь"}`; это ещё не параметры подбора |
| `POST /api/calendar` | Поля запроса; город и категория обязательны, остальные могут отсутствовать | `candidate_count`, `days: [{date, free, busy}]`, `months: [{month, days, free_days, busy_percent}]`, `data_version` |
| `POST /api/matches` | Подтверждённые поля ниже | `status`, `cards`, `total`, `candidate_count`, `excluded`, `message`, `ranking`, `notice`, `data_version`, `date_alternatives` |

`date_alternatives` — отдельный массив профилей с `dates: ["YYYY-MM-DD"]`; это предложения изменить дату, не совпадения на исходную дату. Остальные поля профилей и флаги происхождения сохранены. `POST /api/calendar` возвращает все 100 известных дней; выбранная `event_date` не меняет статистику, но, если передана, должна быть внутри покрытия.

Пример запроса при запущенном сервере:

```bash
curl http://127.0.0.1:8080/api/matches \
  -H 'Content-Type: application/json' \
  -d '{"city":"Алматы","event_date":"2026-10-06","event_type":"корпоратив","category":"Ведущий","budget_kzt":1300000,"language":"русский","duration_hours":6,"wishes":[],"unverified_requirements":[]}'
```

`language` можно опустить или передать пустой строкой; `duration_hours` — опустить или передать `null`. `wishes` содержит идентификаторы из `/api/options`. Цена — целое число тенге, часы могут быть дробными. Три бизнес-исхода возвращают HTTP 200: `matches_found`, `category_unavailable`, `no_matches`. Ошибки входных данных — 400/422, недоступный разбор AI — 503; тело ошибки: `{"error":{"code":"...","message":"..."}}`. Счётчики причин исключения могут пересекаться.

Для аудио: 400 — пустая/неверная multipart-запись, 413 — превышение размера, 415 — неподдерживаемый или подменённый формат, 503 — распознавание недоступно. `/api/options` содержит `voice_enabled` (настроен ключ), `ai_enabled` и `semantic_enabled`; доступ к реальному API проверяется при обращении. Ошибка БД — 503 с кодом `DATABASE_UNAVAILABLE`.

### Повторяемость

Сортировка не вызывает языковую модель и не вычисляет новые векторы запросов. Она использует неизменный индекс, фиксированный порядок суммирования, округление оценки до миллионных, цену и `id`. Дубли пожеланий удаляются, порядок их выбора не влияет на результат.

Гарантия относится к **одинаковым подтверждённым полям и пожеланиям при одинаковой версии данных, индекса и кода**. Первичный разбор свободного текста внешней моделью может различаться; поэтому поля показываются для подтверждения. `temperature=0` и кеш не используются как доказательство повторяемости.

Версия нормализованных профилей из БД, цитат, календаря и словаря пожеланий проверяется при загрузке и на каждом запросе; устаревший индекс не используется. Изменение БД отключает несовместимый индекс с явным переходом к порядку по цене. Для нового каталога сохраните прежний файл индекса отдельно, подготовьте новый и перезапустите сервер. Индекс, созданный старой версией приложения до PostgreSQL, также требует повторной подготовки. В ответе поиска есть `data_version`, включающий отпечаток самого индекса. После создания **сохраните `data/semantic-index.json` вместе с решением в Git**: в нём нет API-ключа. Один и тот же файл нужен для повторения смыслового порядка на другой машине. Повторная генерация через внешний API создаёт новую версию данных и может менять порядок.

## Данные и происхождение

`data/catalog.csv` — копия переданного организаторами CSV без изменения содержимого. HTML-превью не используется: в нём сокращены 39 описаний.

- 50 профилей Алматы, 15 Астаны, один с обозначением «Зарубежье». Выезды, упомянутые в описаниях, не расширяют поле города.
- 13 исходных синтетических профилей, восемь дополненных городов, 18 дополненных цен. Флаги сохранены и показаны в карточках. `data_origin: organizer` отличает их от добавлений команды; в рабочем каталоге добавлений команды нет.
- `data/evidence.json` — выбранные при разработке AI-агентом и проверенные цитаты, а не новые сведения о подрядчиках. При старте каждая цитата проверяется на буквальное присутствие в исходном описании.
- `max_hours` пусто у девяти профилей: услуга не привязана к присутствию на площадке. Такие записи не исключаются по длительности.
- `price_from_kzt` — цена «от» за мероприятие; не умножается на часы и не гарантирует итоговую стоимость.
- Занятость проверяется у всех, включая площадки. За пределами 23.09.2026–31.12.2026 подбор недоступен.

## Как проверить

```bash
go test -race ./...
go vet ./...
```

Тесты используют исходный каталог и локальный тестовый AI-сервис: проверяют ограничения, занятость площадок, редкие категории, пустую выдачу, непроверяемые условия, ошибки формата, происхождение цитат, сохранение и повторную загрузку индекса, изменение порядка по пожеланиям. Для этих тестов ключ и интернет не нужны. Контрольные векторы в тестах не являются результатом настоящей модели.

`calendar_test.go` сравнивает количество свободных подрядчиков в календаре с результатами строгого подбора на всех 100 днях, проверяет месячные проценты, границы покрытия, пустые выборки, `max_hours=null`, порядок ближайших дат и то, что альтернативы действительно проходят все условия. В Firefox проверены главная, календарь с клавиатурой, подтверждение альтернативной даты, диктовка и основные страницы при точной ширине 320, 768, 1024 и 1440 px.

`voice_test.go` проверяет передачу записи в API, ограничения формата и размера, пустую расшифровку, отсутствие ключа и сбой провайдера. Для проверки настоящего PostgreSQL:

```bash
docker compose up -d --wait db
TEST_DATABASE_URL='postgres://eventmatch:eventmatch_local@127.0.0.1:5432/eventmatch?sslmode=disable' go test -race ./...
```

При других настройках задайте `TEST_DATABASE_URL` через окружение. Тест создаёт и удаляет **собственную отдельную БД**; требуется право `CREATE DATABASE`. Рабочий каталог не очищается. Проверяются полный перенос 66 профилей с календарём и происхождением, откат ошибочного импорта, одновременные старты, сохранность изменений при повторном запуске, обновление выдачи после изменения занятости, отключение старого индекса и недоступность БД.

При разработке также проверены реальная запись через `MediaRecorder` в Firefox с искусственным источником звука, добавление текста, подтверждение, отмена, ошибка распознавания, уход со страницы и отказ в разрешении. Ответ распознавания подменялся тестовым: качество настоящего распознавания нужно проверить после настройки ключа. Для ручной проверки продиктуйте пример ниже, исправьте текст, подтвердите поля; отдельно отмените запись и проверьте, что исходное описание сохранилось.

В интерфейсе есть кнопки трёх примеров, которые сначала открывают подтверждение:

| Сценарий | Условия | Ожидаемое поведение |
|---|---|---|
| Массовая категория | Алматы, ведущий, корпоратив, 06.10.2026, 1 300 000 ₸, русский, 6 ч, без пожеланий | Семь проходят условия; карточки: Куррапика, Мицури Канроджи, Аня Форджер |
| Повтор | Тот же запрос | Те же три карточки в том же порядке |
| Смена даты | Из предыдущего результата изменить только дату на 02.10.2026 | Кики и Буллма; объяснение исключения прошлой тройки по занятости |
| Редкая категория | Астана, флорист, свадьба, 01.10.2026, 300 000 ₸, русский | Хаку — единственный профиль категории в городе |
| Все заняты | Тот же флорист на 02.10.2026 | Нет совпадений; отдельно Хаку и ближайшие дни без занятости: 03.10, 01.10, 30.09. Выбор даты сначала открывает подтверждение |
| Категории нет | Астана, декоратор, свадьба, 01.10.2026, 2 000 000 ₸ | Категории нет в этом городе |

После настройки AI проверьте текст: «Ведущий на корпоратив в Алматы 6 октября 2026, до 1 300 000 тенге, на русском, на 6 часов, спокойная подача». Убедитесь, что параметры и пожелание видны до подтверждения. Сравните с «динамичная программа» при тех же полях; конкретный смысловой порядок нужно проверить на подготовленном индексе, а не объявлять заранее.

## Ограничения

- Живая проверка OpenAI требует ключа. Без индекса смысловой подбор явно отключён; без ключа отключены разбор свободного текста и диктовка.
- Смысловой индекс использует по одной выбранной цитате на профиль. Полные описания могут содержать дополнительные детали, которые не влияют на смысловой порядок первой версии.
- Автоматический разбор может ошибаться; подтверждение полей обязательно. Правильный JSON сам по себе не доказывает правильность понимания.
- Поля и описания иногда расходятся. Для строгих проверок приоритет у полей; заявления из описаний не считаются независимо подтверждёнными отзывами, наградами или гарантиями.
- Нет бронирования, заявок, оплаты, уведомлений, автоматического ослабления условий, дообучения и интеграции с API Firebird.
- Состояние формы хранится в памяти вкладки и сбрасывается при перезагрузке. Шрифты загружаются с Google Fonts; есть системный запасной шрифт.
- Сервер рассчитан на локальную демонстрацию. Публичное размещение и защита расходов API для публичного сервиса отдельно не настроены. Развёрнутой публичной версии нет.

При разработке использован AI-агент Codex: интеграция интерфейса, сервер, выбор цитат, тесты и документация. Итоговую версию необходимо сдать через платформу хакатона; отправка кода в GitHub сама по себе не является сдачей.
